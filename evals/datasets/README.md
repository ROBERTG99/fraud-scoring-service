# Eval datasets

Generated by `scripts/gen_eval_sets.py` with seed 7 (`uv run python scripts/gen_eval_sets.py`); never edited
by hand. Each set has a `dev.jsonl` and a `test.jsonl` partition and `cases.v1.jsonl` (dev then test), the
single file an `evalgate.suite.v1` reads. `MANIFEST.json` pins the SHA-256 of every file;
`tests/unit/test_eval_sets.py` checks counts, disjoint splits, the manifest and byte-identical regeneration.
Rows use the upstream evalgate case shape `{id, split, input, expected, tags, meta}` (D-030, D-031).

| Set | Dev / test | Input | Label (by construction) |
|---|---|---|---|
| `decisions` | 60 / 90 | transaction, 13 features (or `null`: Redis down), model score (or unavailable) | action, reason-code set, degraded flag, from `rules/rules.v2026.10.2.yaml` and the combination table; 15 templates x 10 (rules, near misses, band edges, degraded paths) |
| `summaries` | 48 / 72 | a REVIEW case as the summarizer loads it (decision, features, events) | pattern of the generating scenario (`cmd/gen/PATTERNS.md`): takeover 30, card testing 20, mule 20, friendly fraud 20, unclear (legitimate look-alikes) 30; `meta.pii` lists synthetic PII planted in merchant names |
| `judge_calibration` | 40 / 40 | case facts and a summary | useful (written from the facts) or not (wrong pattern, wrong number, absent fact, generic checks); 20 / 20 per split |

The earlier name `judge_calibration.v1.jsonl` is `judge_calibration/cases.v1.jsonl`.
