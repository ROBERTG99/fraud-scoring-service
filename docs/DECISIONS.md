| D-020 | 2026-10-16 | The HTTP contract is strict and stated in the OpenAPI: request constraints (patterns, ranges, enums, required, `additionalProperties: false`) are added by `scripts/openapi_v3.py` from the server's validators; the HTTP layer rejects anonymous calls with 401 before decoding, unknown query parameters, numeric enum values and JSON `null` with 400, and wrong methods with 405 + `Allow` (derived from the proto `google.api.http` rules). | D-021 | 2026-10-16 | Console users are rate limited per subject (token bucket, `FRAUD_RATE_LIMIT_RPS`, default 20, burst 20, `0` disables); the service principal on `Score` is not, because the writer queue already returns `RESOURCE_EXHAUSTED`. `FRAUD_REDIS_PREFIX` (default `fr`) is shared by scorer and feature-updater. | Limit `Score` too; a global limit. | NFR-9 is "20 req/s per user"; limiting `Score` would cap the 1,000 RPS load target. | D-022 | 2026-10-16 | The summarizer checks `processed_messages` before running and records the `decision_id` only after the summary is persisted; `case_summaries` inserts are `ON CONFLICT DO NOTHING` (regenerate upserts). Invalid `decisions` messages go to `events.dlq`; a transient failure commits the processed prefix, seeks back and retries. The decision's own transaction comes from `decisions.tx`; `account_events` adds up to 49 earlier events. | D-024 | 2026-10-17 | Seed replays the last 72 h of the demo data (the held-out test split; on gen v1 data 16,863 transactions with 174 frauds, on gen v2 16,902 test-split transactions and 16,904 scored in the window) at 250 tx/s, not 24 h.
